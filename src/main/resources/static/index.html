Backend Architecture & REST API Guide
1. Layered Architecture Flow

In this application, incoming requests follow the standard Spring Boot layered design pattern:

Client (Fetch API) ➔ Controller (@RestController) ➔ Service (@Service) ➔ Repository (@Repository / Spring Data JPA) ➔ MySQL Database
2. REST API Endpoints Reference
HTTP Method Endpoint Purpose
POST /api/tasks Create a new task in MySQL
GET /api/tasks Retrieve all tasks (supports keyword, status, priority, sort)
GET /api/tasks/{id} Get single task by primary key
PUT /api/tasks/{id} Update full task details
PATCH /api/tasks/{id}/status Update only status (Pending, In Progress, Completed)
DELETE /api/tasks/{id} Delete task from MySQL
GET /api/tasks/search?keyword=... Search tasks by title
GET /api/tasks/filter?status=... Filter tasks by status and priority
GET /api/tasks/stats Get aggregated counts for dashboard
3. Educational Mentoring Tips
  • Why DTOs? Decouples internal database entities from external API contracts. Prevents client from altering restricted fields.
  • Why Hibernate ddl-auto=update? Automatically generates or alters the table schema when you run the app.
  • Why @RestControllerAdvice? Centralizes error handling so controllers don't need repetitive try-catch blocks.
